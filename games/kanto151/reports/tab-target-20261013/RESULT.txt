Tab 대상 전환 개선 결과 — 2026-10-13

완료: 로컬 구현·검수·배포용 빌드. 공개 사이트 반영은 사용자가 승인했으며 기존 TCG HUB 배포 경로로 진행.

조작
- Tab / Q: 주변의 다음 공격 대상.
- Shift+Tab: 이전 공격 대상.
- 모바일 ‘대상’ 버튼: 다음 공격 대상. 포켓몬 직접 클릭·짧게 터치도 유지.
- 누르고 있는 Tab의 자동 반복은 무시하며 한 번 누를 때 한 번 전환.
- 메뉴·도감 검색창·입력칸에서는 원래 Tab 버튼 이동을 유지. Ctrl/Alt/Meta+Tab도 게임 대상으로 처리하지 않음.

동작
- 처음에는 가까운 순서로 시작하고, 상대가 이동해도 남아 있는 개체의 순서를 유지.
- 새로 들어온 상대는 기존 순환 뒤에 추가. 같은 종도 개체 객체를 기준으로 구분.
- 30m 이상 떨어진 개체, 쓰러짐, 포획 중, 숨겨진 모델은 건너뜀.
- 현재 상대가 제거되면 그 자리 다음 개체로 전환. 지역 변경 시 이전 명단을 재사용하지 않음.
- 로딩·사망·복원·친구 교체·포획·메뉴 중에는 전환하지 않음.
- 대상 이름·선택 이름표를 즉시 갱신. 대상만 바꾸며 카메라 각도·거리·준비 중인 기술·재사용 시간을 초기화하지 않음.
- 이미 준비 중인 기술은 처음 겨냥한 상대에게 나가고, 다음 기술은 새로 선택한 상대를 공격.
- 설정과 부족한 대상 안내에 한국어·영어 조작 설명 추가.
- 앞서 수정한 만료된 야생 대기 타이머의 선공 취소 및 솔라빔 경로 판정 수정도 보존.

실제 검사 결과
- 자동 검사 338개 통과, 실패·건너뜀 0개. 기존 전투·진화·저장·복귀·진행 검사 포함.
- 소스와 빌드 각각 대상 전환 36개 상황 통과: PC 1280×720, 모바일 세로 390×844·가로 844×390.
- 각 화면에서 실제 꼬렛 세 마리 모두 반격하며 정방향·역방향·Q·반복 입력·같은 종 개체 구분·사라진 대상·직접 클릭/터치·모바일 대상 버튼·메뉴 포커스 검사.
- 실제 배운 솔라빔을 준비하는 중 대상 변경 후 원래 상대에게 피해가 적용되고, 정상 재사용 시간이 지난 뒤 다음 기술은 새 상대에게 적용됨.
- 최종 빌드에서 선공 회귀 15개 상황 통과: 할퀴기·몸통박치기·물대포·불대문자·솔라빔 × PC/모바일 3개 화면. 선공 피해 후 야생 반격이 이어짐.
- 브라우저 오류 0개. audit와 build 통과.
- 소스·빌드·실제 HTTP 파일 71개 내용 일치. 현재 사이트 기준 66개 모듈/데이터/시작 화면/스타일 동일.
- 종·지역·기술 수치·개체 저장·보급·진행·카메라 데이터는 변경하지 않음. 151종·5지역 전체 자연 수집을 새로 반복한 것은 아니며 기존 전수 증거는 원래 검수 버전으로 보존.

검사 환경과 남은 제한
- 새 브라우저 세션의 qa=1 메모리 저장 사용. 실제 사용자 저장을 읽거나 변경하지 않음.
- 전투를 충분히 관찰하기 위해 실제 모델·실제 지형 위에서 높은 체력, 레벨, 초기 공격 타이머를 준비함. 게임 데이터의 실제 체력·레벨·전투 수치는 변경하지 않음.
- 모바일은 Edge 화면·터치 재현. 실물 휴대폰과 Safari는 미검증.
- 처음 검사에서 잘못된 설정 버튼 이름, 검색창 포커스 상태의 닫기 절차를 바로잡음.
- 첫 빌드 직접 터치 검사는 겹친 모델 가장자리에서 빗나갔고, 다음 준비 위치는 세로 화면 밖에 나감. 원래 실패 기록은 harness-* 파일에 보관. 최종 직접 선택 검사는 합법적인 잘 보이는 위치와 별도로 준비한 거리 28의 카메라에서 내부 유효 지점을 확인한 뒤 일반 클릭/터치로 수행. 기존 가려진 모델 클릭 차단 규칙은 유지.

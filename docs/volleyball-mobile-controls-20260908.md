# Mobile simultaneous controls — 2026-09-08

The user reported that simultaneous mobile actions were difficult or unavailable. The previous pointer map already supported distinct pointer IDs, but action drags stayed bound to their starting action and all viewport height changes paused the game and cleared inputs. No physical-device cause was confirmed; device/browser details were requested.

Touch-capable browsers now handle every changedTouches identifier independently with nonpassive Touch Events. Pointer Events remain for mouse/pen and for touch when Touch Events are unavailable; duplicate touch pointer events are ignored only when the native touch path is enabled. Releasing or canceling one contact preserves other contacts. Group gaps accept neutral starts, and action drags can switch buttons. Neutral drift preserves a one-shot action and returning to the same button does not retrigger it. Pad gaps and the active court suppress browser gestures, and pressed feedback no longer moves input hitboxes.

The large mobile attack button now initiates one jump and one strike near the upper portion of that jump. An airborne press strikes directly; no ball targeting or repeated automatic jumps occur. This uses ordinary sampled jump/spike bits under existing rules v4, so server replay and leaderboard records remain compatible. Keyboard Space remains a manual spike. Height-only browser chrome resizing no longer pauses play; width/orientation changes and hidden pages still do.

Validation: all 34 input tests and screen lifecycle tests pass, including changedTouches batches, secondary pointer fallback, independent release/cancel, transport deduplication, drift, action switching, no repeat across landing/rally reset, and identical replayed engine state. Existing gameplay and member API tests pass. A temporary browser harness using constructed TouchEvent/Touch and PointerEvent objects passed four DOM event scenarios; it was removed from the game directory after verification. This tests application event handling, not hardware/browser gesture delivery. Actual game UI verified the combined attack and continued play through a height-only viewport change; 320 px and 390 px portrait layouts were inspected. Physical phone testing remains outstanding.

Standards checked: [W3C Pointer Events](https://www.w3.org/TR/pointerevents3/), [MDN changedTouches](https://developer.mozilla.org/en-US/docs/Web/API/TouchEvent/changedTouches).
